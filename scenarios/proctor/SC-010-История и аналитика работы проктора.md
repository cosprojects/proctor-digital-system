# SC-010

## 1. Общая информация

- Код сценария: SC-010
- Роль: Proctor
- Название: История собственных проверок проктора

---

## 2. Цель сценария

Предоставить проктору историю собственных проверок и доступ к ранее просмотренным сессиям: завершённые проверки, поиск прошлой сессии, просмотр собственного решения.

Глобальная аналитика (нагрузка, распределение, quorum, pool, journal системы) — функция Administrator и в этот сценарий не входит.

## 4. Preconditions

- у проктора есть завершённые проверки;
- данные о проверках сохранены;
- Attempt в состоянии Decision Made / Published / Archived.

---

## 5. Trigger

Проктор открывает историю и аналитику своей работы.

---

## 6. Основной сценарий

1. Система открывает историю собственных проверок проктора.
2. Отображается история проверок со статусами и датами.
3. Проктор использует фильтры по периоду / статусу.
4. Проктор открывает Session из истории (SC-002 / SC-008).
5. При необходимости проктор просматривает собственное решение (SC-006).
6. Проктор возвращается к работе (SC-001).

---

## 7. Альтернативные сценарии

### Нет данных

Система сообщает об отсутствии завершённых проверок за выбранный период.

---

### Доступ ограничен

Система сообщает об отсутствии прав на часть данных.

---

### Переход к повторной проверке

Проктор открывает Session из истории и при необходимости просматривает собственное решение (SC-006).

## 11. Функциональные элементы

### History Summary

- количество завершённых собственных проверок;
- количество проверок в работе.

Аналитические показатели собственной работы (время обработки, доля подтверждённых Observation) не подтверждены источниками и не являются обязательной частью MVP.

### History List

- список проверок;
- Session;
- дата;
- статус;
- итоговое Decision.

### Filters

- период;
- статус проверки;
- итоговое Decision.

### Session Link

- открытие Session из истории (SC-002 / SC-008);
- просмотр собственного решения (SC-006).

## 13. Edge Cases

- нет данных за период;
- часть данных недоступна по правам;
- показатели изменяются во время просмотра;
- ошибка загрузки истории.

---

## 14. Критерии успеха

Сценарий считается завершенным, если:

- история собственных проверок доступна;
- проктор может открыть Session из истории;
- проктор вернулся к работе.
