# SC-005

## 1. Общая информация

- Код сценария: SC-005
- Роль: Proctor
- Название: Принятие Decision и формирование Conclusion

---

## 2. Цель сценария

Позволить проктору принять итоговое Decision по Session, сформировать Conclusion и Comment и завершить проверку.

Итоговое заключение формирует проктор. Итоговые показатели (результат, показатель качества / доверия) рассчитываются системой и не редактируются проктором вручную.

Автоматические показатели не являются окончательным решением сами по себе.

## 4. Preconditions

- Session открыта (Attempt);
- Observation проанализированы (SC-004);
- Evidence проверено при необходимости (SC-003);
- Attempt в состоянии Review Required;
- Recommendations AI доступны (при наличии).

---

## 5. Trigger

Проктор переходит к принятию Decision по Session.

---

## 6. Основной сценарий

1. Система отображает итоговую сводку Session:
   - Risk Score;
   - показатель качества / доверия;
   - подтверждённые Observation;
   - отклонённые Observation;
   - исключённые Metric;
   - Recommendations AI.
2. Проктор принимает итоговое Decision по Attempt (Approved / Rejected; полный набор значений Decision определяется доменной моделью).
3. Проктор формирует Conclusion — обоснование принятого решения.
4. Итоговые показатели (результат, показатель качества / доверия) рассчитываются системой; проктор не вводит их вручную. При исключении Metric пересчёт выполняется системой (SC-004).
5. Проктор оставляет Comment. При Decision Rejected комментарий обязателен (Comment required); при Approved — по необходимости.
6. Система фиксирует Decision, Conclusion и Comment.
7. Система переводит Attempt в состояние Decision Made.
8. При необходимости проктор экспортирует отчёт конкретной проверки (PDF); ZIP / deep archive — только при разрешении настройками / шаблоном.

## 7. Альтернативные сценарии

### Недостаточно данных для Decision

Attempt остаётся в состоянии Review Required.

Проктор оставляет Comment о причине и возвращает Session в список.

---

### Decision принято ранее

Система отображает историю; повторное принятие недоступно.

Изменение принятого Decision — административная функция (SA-003).

---

### Массовые операции

Массовое принятие Decision по группе Attempt допускается только при наличии бизнес-правил.

## 11. Функциональные элементы

### Review Summary

- Risk Score;
- показатель качества / доверия;
- подтверждённые Observation;
- отклонённые Observation;
- исключённые Metric;
- Recommendations AI;
- Attempt status;
- итоговый результат, рассчитанный системой (после пересчёта при исключении Metric).

### Decision Panel

- Decision (Approved / Rejected; полный набор значений — доменная модель);
- при Decision Rejected комментарий обязателен (Comment required);
- Comment;
- Comment Suggestions: система отображает релевантные формулировки, связанные с контекстом Attempt / Observation / Risk; проктор нажимает на Suggestion, текст вставляется в поле Comment и может быть отредактирован; Suggestion не отправляется автоматически и не принимает Decision за проктора;
- подтверждение Decision;
- отмена действия до подтверждения.

### Conclusion Editor

- формирование Conclusion;
- сохранение Conclusion;
- обоснование Decision.

### Comment

- комментарий проктора;
- комментарий для последующей проверки.

### Export

- экспорт отчёта конкретной проверки (PDF);
- ZIP / deep archive — только при разрешении настройками / шаблоном;

## 13. Edge Cases

- ошибка сохранения Decision;
- изменение Attempt статуса во время принятия Decision;
- повторное открытие Session после сохранения;
- отмена действия до подтверждения;
- недоступность экспорта отчёта.

---

## 14. Критерии успеха

Сценарий считается завершенным, если:

- принято итоговое Decision;
- сформированы Conclusion и Comment;
- при Decision Rejected комментарий предоставлен;
- Decision сохранено;
- Attempt переведён в Decision Made;
- проктор перешёл к следующей проверке.
