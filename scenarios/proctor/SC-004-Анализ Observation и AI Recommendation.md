# SC-004

## 1. Общая информация

- Код сценария: SC-004
- Роль: Proctor
- Название: Анализ Observation и AI Recommendation

---

## 2. Цель сценария

Позволить проктору проанализировать Observation и Recommendation AI по Session, определить, какие Observation подтверждаются контекстом, и подготовить основу для принятия Decision.

Observation — событие / факт / сигнал, результат анализа evidence. Observation не является метрикой и не является Decision.

Отдельно от Observation существует Metric — показатель, участвующий в расчёте. Исключение Metric из расчёта — отдельная операция (post-review recalculation).

Автоматические показатели (Risk Score, показатель качества / доверия) не являются итоговым заключением; итоговое заключение формирует проктор.

Показатель качества / доверия — термин из фактических вводных, не закреплён в GLOSSARY.

## 4. Preconditions

- Session открыта (SC-002);
- Observation и Recommendations AI доступны;

- Attempt в состоянии Review Required.

## 5. Trigger

Проктор переходит к анализу Observation из открытой Session.

---

## 6. Основной сценарий

1. Система отображает список Observation Session.
2. Для каждого Observation отображается:
   - тип;
   - время возникновения;
   - продолжительность;
   - уровень уверенности AI;
   - объяснение (Explainable AI);
   - ссылка на evidence.
3. Отображается Recommendation AI и её объяснение.
4. Проктор анализирует каждое Observation с учётом контекста и evidence.
5. Проктор принимает решение по Observation:
   - подтвердить Observation;
   - отклонить Observation;
   - признать Observation нерелевантным.
   Исключение Observation из расчёта не выполняется: Observation не является метрикой.
6. Система фиксирует решения проктора по Observation.
7. Отдельным действием проктор может исключить из расчёта Metric (показатель), участвующую в расчёте итогового результата (post-review recalculation):
   - система фиксирует изменение;
   - метрика исключается из расчёта;
   - результат и связанный показатель качества / доверия пересчитываются системой;
   - новый результат отображается;
   - предыдущий результат сохраняется в истории;
   - запрашивается причина изменения (если это предусмотрено моделью).
   Проктор не вводит Risk Score, Trust / Confidence и Result вручную — производные значения рассчитывает система.
8. Проктор переходит к принятию Decision (SC-005).

---

## 7. Альтернативные сценарии

### Ложное срабатывание

Проктор отклоняет Observation; Recommendation AI (Ignore) подтверждается.

---

### Observation не подтверждается контекстом

Проктор отклоняет Observation.

Если с Observation связана Metric, участвующая в расчёте, проктор может исключить её отдельным действием (связь Observation → Metric описывается как связь объектов, а не автоматическое равенство).

---

### Повторяющиеся Observation

Система отображает агрегированное Observation с указанием количества повторений.

---

### Недостаточно данных для оценки

Проктор возвращается к Evidence (SC-003) для проверки контекста.

---

### Конфликт Observation

Система отображает противоречащие друг другу Observation; проктор оценивает их по отдельности.

## 11. Функциональные элементы

### Observation List

- список Observation;
- тип;
- время возникновения;
- статус рассмотрения.

### Observation Card

- тип Observation;
- время возникновения;
- продолжительность;
- уровень уверенности AI;
- решение проктора.

### Recommendation Panel

- Recommendation AI;
- объяснение Recommendation;
- уровень уверенности.

### Explainability Panel

- факторы, повлиявшие на Recommendation;
- перечень Observation;
- ссылки на фрагменты записи;
- уровень уверенности AI.

### Evidence Links

- переход к Evidence (SC-003);
- автоматическое позиционирование записи.

### Risk Impact

- показатели (Risk Score, показатель качества / доверия) рассчитываются системой на основе включённых метрик;
- исключение Metric из расчёта — отдельное действие проктора;
- проктор не вводит Risk Score, Trust / Confidence и Result вручную;

<!-- TODO: BUSINESS RULE REQUIRED — формула расчёта показателей и правила пересчёта при исключении Metric не определены. -->

- итоговый Risk Score;
- показатель качества / доверия;
- отметка, что автоматические показатели не являются итоговым заключением.

### Metric Exclusion

- перечень метрик, включённых в расчёт;
- состояние метрики (включена / исключена);
- действие «исключить метрику из расчёта»;
- причина исключения (комментарий);
- история пересчётов (предыдущий и новый результат);

```text
METRIC → включена в расчёт → Proctor отключает metric → Recalculation → Updated result / confidence
```

## 13. Edge Cases

- ложное срабатывание AI;
- повторяющиеся Observation;
- большое количество Observation;
- Observation без evidence;
- конфликт Observation;
- изменение показателей после пересчёта (исключение Metric);
- пересчёт показателя качества / доверия после исключения Metric;
- Recommendation отсутствует (Degradation Mode).

---

## 14. Критерии успеха

Сценарий считается завершенным, если:

- все Observation проанализированы;
- по каждому Observation принято решение проктора;
- Recommendation AI не смешаны с Decision;
- при необходимости выполнено исключение Metric с пересчётом показателей системой;
- проктор перешёл к принятию Decision (SC-005).
