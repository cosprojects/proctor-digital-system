# SC-007

## 1. Общая информация

- Код сценария: SC-007
- Роль: Proctor
- Название: Переход к следующей проверке

---

## 2. Цель сценария

Обеспечить непрерывную работу проктора: после завершения проверки Session система предлагает следующую назначенную Session согласно текущей очереди без ручного поиска.

---

## 4. Preconditions

- текущая проверка Session завершена (Decision принято);
- Attempt переведён в Decision Made;
- в очереди проктора есть другие назначенные Session;
- приоритеты очереди актуальны.

---

## 5. Trigger

Проктор завершает текущую проверку Session (SC-005).

---

## 6. Основной сценарий

1. Система фиксирует завершение текущей проверки.
2. Система предлагает следующую назначенную Session согласно текущей сортировке / приоритету очереди.
3. Система отображает предложение следующей проверки с краткой информацией.
4. Проктор подтверждает переход.
5. Система открывает следующую Session (SC-002).
6. Проктор приступает к проверке.

## 7. Альтернативные сценарии

### Очередь пуста

Система сообщает об отсутствии назначенных Session.

Проктор возвращается в рабочий список Attempt (SC-001) или завершает работу.

---

### Появилась Session с более высоким приоритетом

Система предлагает её в первую очередь.

---

### Текущая Session требует доработки

Проктор возвращает Session в список с Comment; следующая проверка определяется без неё.

---

### Возвращённая Session

Система предлагает возвращённые проверки с указанием причины возврата.

## 11. Функциональные элементы

### Next Item Preview

- краткая информация о следующей сессии;
- показатели сессии (Risk Score, показатель качества / доверия);
- срок проверки;
- количество Observation.

### Queue Position

- количество оставшихся назначенных Session;
- позиция в очереди.

### Priority Indicator

- причина приоритета;
- срочность проверки.

### Waiting State

- сообщение об отсутствии назначенных Session;
- возврат в рабочий список Attempt.

## 13. Edge Cases

- очередь пуста;
- приоритет изменился во время перехода;
- Session переназначена;
- Session возвращена в список;
- потеря соединения при открытии следующей Session.

---

## 14. Критерии успеха

Сценарий считается завершенным, если:

- следующая назначенная сессия предложена согласно текущей сортировке очереди;
- проктор перешёл к следующей проверке;
- очередь актуализирована.
