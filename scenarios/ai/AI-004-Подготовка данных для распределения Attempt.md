# AI-004

## 1. Общая информация

- Код сценария: AI-004
- Роль: System AI
- Название: Подготовка данных для распределения Attempt (Assignment)

---

## 2. Цель процесса

Подготовить данные о Attempt со статусом Review Required для последующего распределения между прокторами и обеспечить информацию для равномерной загрузки специалистов.

---

## 3. Назначение процесса

После завершения анализа отдельных Attempt система определяет Attempt, требующие человеческого Review, и формирует данные для их распределения между доступными прокторами.

AI подготавливает приоритет, оценку трудоёмкости, прогнозируемое время Review и необходимые данные для распределения.

AI не назначает Attempt проктору: распределение Attempt между прокторами — административная зона ответственности (SA-003); конкретный механизм и алгоритм распределения не определены.

Модель Review Batch не используется.

---

## 4. Preconditions

- завершены процессы AI-001 и AI-003;
- сформированы Recommendations;
- доступны Attempt, ожидающие проверки (Review Required);
- известны доступные прокторы.

---

## 5. Trigger

Attempt получает статус Review Required и становится доступным для распределения.

---

## 6. Основной сценарий

1. AI определяет Attempt со статусом Review Required.
2. Исключает Attempt, для которых System применила Auto Decision (по бизнес-правилам; AI не принимает Decision).
3. Для каждого Attempt оценивает:
   - уровень риска;
   - предполагаемую трудоемкость рассмотрения;
   - прогнозируемое время проверки.
4. Подготавливает данные о текущей загрузке прокторов.
5. Передает подготовленные данные (приоритет, трудоёмкость, прогноз времени Review) в административный процесс распределения; AI не назначает Attempt проктору.

6. Связанные Attempt остаются в состоянии Review Required до принятия Decision.

---

## 7. Альтернативные сценарии

### Все Attempt получили System Auto Decision

Attempt для распределения отсутствуют.

---

### Нет свободных прокторов

Attempt остаются в Review Required и ожидают распределения.

---

### Обнаружены критические Attempt

Критические Attempt отмечаются для приоритетного распределения.

---

## 8. System Flow

Attempt (Review Required)

↓

Фильтрация (Auto Decision)

↓

Оценка трудоемкости

↓

Данные о загрузке прокторов

↓

Данные для распределения Attempt

---

## 9. Functional Zones

- Attempt Identification
- Workload Data
- Assignment Data
- Priority Marking

---

## 10. Функциональные элементы

### Для зоны "Attempt Identification"

- количество Attempt в Review Required;
- распределение по категориям риска;
- средний Risk Score.

---

### Для зоны "Workload Data"

- текущая нагрузка прокторов;
- количество назначенных Review Required Attempt;
- уровень загрузки.

---

### Для зоны "Assignment Data"

- подготовленные данные для распределения;
- статус готовности.

---

### Для зоны "Priority Marking"

- отметка критических Attempt;
- приоритет рассмотрения.

---

## 11. Required Components

- Attempt Card
- Workload Indicator
- Assignment Status
- Priority Badge

---

## 12. Edge Cases

- данные о загрузке неполны;
- часть Attempt была повторно обработана;
- Attempt содержит только критические случаи;
- проктор недоступен после распределения;
- Attempt требует перераспределения.

---

## 13. Критерии успеха

Процесс считается завершенным, если:

- Attempt в Review Required идентифицированы;
- подготовлены данные о загрузке прокторов;
- данные для распределения переданы;
- связанные Attempt остаются в состоянии Review Required.

---
