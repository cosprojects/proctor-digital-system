# Design System & Scenario Development Rules

Версия: 1.0

## Цель

Проект развивается через последовательное проектирование пользовательских сценариев.

Каждый новый сценарий оформляется как отдельный визуальный артефакт Figma на основе существующей дизайн-системы.

Дизайн-система является единственным источником истины для всех переменных, компонентов и паттернов.

---

# Основной принцип

Любой новый артефакт обязан использовать существующую дизайн-систему.

Создание новых компонентов допускается только при отсутствии подходящего решения.

Создание дубликатов компонентов запрещено.

---

# Принцип развития дизайн-системы

При создании нового сценария агент обязан соблюдать следующий порядок работы.

## Шаг 1

Проанализировать существующую структуру проекта.

## Шаг 2

Проверить существующие:

- Variables
- Design Tokens
- Components
- Component Sets
- Variants
- Patterns

## Шаг 3

Максимально использовать существующие элементы.

## Шаг 4

Если необходимого элемента не существует:

- создать новую переменную;
- создать новый компонент;
- либо создать Variant существующего компонента.

## Шаг 5

После создания сохранить новый элемент в библиотеку проекта.

Только после этого приступать к сборке нового артефакта.

---

# Правила работы с переменными

Перед созданием новой переменной необходимо проверить существующие коллекции.

При отсутствии подходящей переменной:

- создать новую;
- использовать существующую систему именования;
- разместить переменную в соответствующей странице Foundation.

Запрещается создавать одинаковые переменные с разными именами.

---

# Правила работы с компонентами

Перед созданием нового компонента необходимо проверить библиотеку компонентов.

Приоритет:

1. Использовать существующий компонент.
2. Использовать Variant существующего компонента.
3. Расширить Component Set.
4. Создать новый компонент.

Создание дубликатов запрещено.

---

# Правила работы с паттернами

Каждый новый сценарий становится новым паттерном проекта.

Паттерн создается на основе шаблона сценария.

Паттерны размещаются в разделе:

```
10 Scenario and Patterns
```

---

# Правила создания сценариев

Каждый пользовательский сценарий оформляется отдельным артефактом.

Один артефакт = один законченный сценарий.

Каждый сценарий должен содержать:

- Сценарий
- Customer Journey Map
- User Flow
- Карту экранов
- Примечания

Структура шаблона не изменяется без необходимости.

---

# Правила создания экранов

Экраны не создаются напрямую.

Последовательность проектирования всегда одинакова.

```
Сценарий

↓

Customer Journey Map

↓

User Flow

↓

Карта экранов

↓

UI экранов
```

UI является результатом проектирования сценария, а не отправной точкой.

---

# Использование компонентов

Все артефакты должны собираться исключительно из компонентов библиотеки.

При необходимости отсутствующие компоненты автоматически создаются и добавляются в библиотеку.

После добавления новый компонент становится доступным для всех последующих сценариев.

---

# Использование переменных

Все визуальные свойства должны использовать Variables.

Не допускается использование локальных значений:

- цвета;
- радиуса;
- отступов;
- типографики;
- теней;
- размеров.

При отсутствии необходимой переменной агент обязан сначала создать её.

---

# Автоматическое расширение дизайн-системы

Во время работы агент обязан автоматически развивать библиотеку проекта.

Если обнаружено отсутствие:

- компонента;
- варианта;
- переменной;
- токена;

они должны быть созданы до начала построения нового сценария.

---

# Язык проекта

Все создаваемые материалы оформляются на русском языке.

Это относится к:

- заголовкам;
- описаниям;
- текстам;
- комментариям;
- подписям;
- названиям экранов;
- пользовательскому контенту.

Не допускается использование:

- Lorem Ipsum;
- английских заглушек;
- бессмысленного текста.

---

# Итоговый принцип

Каждый новый JSON Prompt должен работать по следующему алгоритму.

1. Проанализировать существующую структуру проекта.
2. Использовать существующие Variables.
3. Использовать существующие Components.
4. При необходимости расширить дизайн-систему.
5. Сохранить новые элементы в библиотеку.
6. Собрать артефакт сценария.
7. Использовать созданный артефакт как основу для дальнейшего проектирования интерфейсов.

Дизайн-система развивается вместе с продуктом.

Сценарии являются первичным артефактом проекта.

Интерфейсы являются результатом проектирования сценариев.
