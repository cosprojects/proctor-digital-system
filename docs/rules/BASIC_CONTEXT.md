# Общая информация

## Цель проекта

Разработать цифровую платформу проведения экзаменов для водителей Яндекс Такси совместно с Департаментом транспорта Москвы.

Платформа должна поддерживать два режима проведения экзамена:

- Синхронный прокторинг (Live Proctoring)
- Асинхронный прокторинг с использованием искусственного интеллекта (AI Proctoring)

На первом этапе MVP основной фокус делается на синхронном режиме. Асинхронный сценарий также проектируется как часть общей архитектуры продукта.

---

# Цель дизайна

Разработать UX/UI платформы, которая позволит:

- показать инвесторам концепцию продукта;
- продемонстрировать основные пользовательские сценарии;
- стать основой для коммерческого предложения;
- использовать макеты в качестве основы дальнейшей разработки.

Важно понимать, что задача не заключается в детальном проектировании всех бизнес-процессов компании.

Необходимо создать качественный продуктовый прототип, демонстрирующий устройство системы.

# Основные сценарии

## Сценарий 1

Синхронный экзамен

Проктор присутствует в режиме реального времени.

Одновременно подключаются до 30 водителей.

Проктор:

- следит за процессом;
- предупреждает;
- блокирует нарушителей;
- завершает экзамен;
- принимает результаты.

---

## Сценарий 2

Асинхронный экзамен

Водитель проходит экзамен самостоятельно.

Система:

- записывает видео;
- анализирует нарушения;
- формирует AI Report;
- отправляет запись проктору.

Проктор просматривает только подозрительные моменты либо подтверждает решение ИИ.

## Уточнение бизнес-процессов (черновик v0.2)

### Границы проектирования

- Точка входа из КИС АРТ (кнопка "Пройти аттестацию") находится вне зоны проектирования.
- В зоне проектирования: все этапы после входа в модуль аттестации.
- Для водителя явно разделяются два режима:
  - синхронный (в фиксированном слоте с проктором);
  - асинхронный (прохождение сейчас с отложенной проверкой).

---

### Driver: синхронный процесс (E2E)

1. Просмотр доступных слотов.
2. Запись на слот.
3. Подтверждение записи + ссылка на вход.
4. Напоминание о времени и требованиях к прохождению.
5. Предэкзаменационная проверка:
   - доступ к камере;
   - качество сети;
   - освещение и ракурс лица;
   - фоновая верификация лица по базе.
6. Вход в сессию и ожидание старта.
7. Прохождение экзамена (10+ вопросов) при непрерывном контроле лица в кадре.
8. Получение результата:
   - passed -> завершение попытки;
   - failed -> окно повторной записи.

---

### Driver: асинхронный процесс (E2E)

1. Выбор режима "Пройти сейчас" с явной маркировкой "результат после проверки".
2. Предэкзаменационная проверка (камера/сеть/свет/ракурс/идентификация) как обязательный этап.
3. Прохождение экзамена с онлайн-контролем нарушений.
4. Завершение попытки и загрузка артефактов (видео, события, телеметрия).
5. Статус "Проверка результатов".
6. Публикация итогового статуса:
   - passed;
   - failed (тест);
   - failed (нарушения);
   - failed (системный сбой, попытка не засчитана, право на повтор без штрафа).

---

### Правила нарушений и завершения попытки

- Автоматические нарушения от ИИ:
  - лицо вне кадра;
  - сильный наклон/поворот головы;
  - второе лицо;
  - закрытая/нечитаемая камера;
  - посторонние голоса (если аудио включено).
- Базовая логика реакции:
  - 1-2 предупреждения -> информирование водителя;
  - 3 предупреждения -> флаг для решения проктора (в синхронном режиме) или автопометка на аннулирование (в асинхронном).
- Принудительное завершение:
  - проктор может исключить участника вручную;
  - система может завершить попытку автоматически при критическом нарушении.
- Классификация причины провала:
  - по вине водителя (нарушения/недостаточный результат теста);
  - не по вине водителя (потеря связи, технический сбой платформы).
- Для "не по вине водителя" назначается повторная попытка без негативной санкции.

---

### Функциональный контур интерфейса Driver

- Экран выбора режима и слота.
- Экран подтверждения записи и требований.
- Экран проверки оборудования и условий:
  - превью камеры;
  - индикатор света/ракурса;
  - индикатор статуса верификации лица;
  - системные подсказки "как исправить".
- Экран ожидания/подключения.
- Экран экзамена:
  - вопрос/варианты ответа;
  - таймер/прогресс;
  - индикатор комплаенса (лицо в кадре, корректный ракурс);
  - предупреждения о риске аннулирования.
- Экран результата и пересдачи.

---

### Функциональный контур интерфейса Proctor

- Вход в сессию и старт экзамена.
- Мониторинг 30-40 участников одновременно.
- Фокус интерфейса:
  - динамическая сетка плиток водителей;
  - закрепление/выделение плиток с нарушениями;
  - быстрые действия на карточке участника (предупредить/исключить/восстановить при ошибке).
- Каналы коммуникации:
  - чат с группой;
  - при необходимости голосовая связь.
- Индикаторы:
  - нарушения от ИИ;
  - статус прохождения теста;
  - статус соединения/камеры.
- После завершения:
  - отчет по группе;
  - список исключенных;
  - причины аннулирования;
  - переход к следующей сессии.

---

### Функциональный контур интерфейса Administrator

- Планирование:
  - расписания сессий;
  - распределение прокторов по сменам/группам.
- Настройки контроля:
  - какие индикаторы считаются критичными;
  - пороги автопредупреждений/автофлагов;
  - включение/выключение этапов аутентификации.
- Операционный контроль:
  - просмотр истории экзаменов и записей;
  - хранение материалов в БД;
  - аудит действий прокторов и системных решений.
- Аналитика и качество:
  - доля успешных/проваленных попыток;
  - причины провалов (тест/нарушение/техсбой);
  - эффективность прокторов (нагрузка, скорость реакции, доля отмен по решению проктора);
  - доля ложных срабатываний ИИ и последующих корректировок проктором.

---

### Бизнес-метрики (MVP)

- Conversion to completion: запись -> завершенная попытка.
- Pass rate: процент успешной сдачи.
- Violation rate: нарушения на 100 попыток.
- Technical fail rate: доля технически сорванных попыток.
- Proctor intervention rate: вмешательства проктора на сессию.
- Proctor override rate: случаи, когда решение ИИ отменено проктором.
- Re-exam lead time: среднее время до пересдачи.
- Throughput per proctor: завершенные попытки на одного проктора за смену.

---

### Ключевые паттерны для дальнейшего проектирования

- Двухконтурный поток исполнения (sync/async) с единым жизненным циклом Attempt.
- State machine для попытки экзамена и статусов комплаенса.
- Human-in-the-loop: ИИ выявляет риск, проктор подтверждает/корректирует решение.
- Graceful degradation: отдельная ветка для технических сбоев "не по вине водителя".
- Event timeline: единая временная шкала событий для аудита и отчетности.

- несколько лиц в кадре

- разрядился телефон

# Экономическая модель (для презентации)

Необходимо показать два сценария эксплуатации.

## Синхронный

Входные параметры:

- количество водителей;
- период обязательной пересдачи;
- окно прохождения (60 / 180 дней);
- процент явки;
- количество групп;
- количество прокторов;
- загрузка рабочих мест.

Результат:

Расчет необходимого количества прокторов и инфраструктуры.

---

## Асинхронный

Входные параметры:

- количество экзаменов;
- производительность AI;
- процент подозрительных экзаменов;
- время проверки одним проктором.

Результат:

Расчет экономии ресурсов по сравнению с синхронным сценарием.
